# 受験番長 Game Design

## Concept

「受験番長」は、熱血コメディ寄りのスケジュール管理ゲーム。番長として仲間を見捨てず、メンツを保ちながら、受験合格に必要な学力を積む。

## Core Loop

1. ターン開始時に現在ステータスを見る。
2. プロローグ後に志望校を選ぶ。
3. 予定カードから 1 枚選ぶ。
4. ステータスが変化し、低確率で事件が起きる。
5. 高校1年春から3年冬まで、全144週を進める。
6. BGMは1学期、夏休み、2学期、3学期の区切りで切り替わる。
7. 志望校ごとの受験圧で、終盤ほどストレスと体力消耗が増える。
8. 卒業式の時期に合否と主人公別の結末が決まる。

## Stats

- `学力`: 合格判定の主軸。
- `人望`: 仲間との関係。低すぎると「孤独」寄りの結末。
- `メンツ`: 番長としての威厳。低すぎると番長の座が揺らぐ。
- `体力`: 行動の実行条件。低いと重い予定を選べない。
- `ストレス`: 高いほど不調になる。100 に近づくと効率が落ちる。

## MVP Scope

- スマホ縦画面。
- カード選択式。
- 高校3年間を144週で遊ぶ。
- UI 中心 + シルエット風の硬派な見た目。
- 外部 API、ログイン、DB、課金、広告は入れない。

## Protagonist Routes

- `受験番長`: 仁義とメンツを背負う硬派ルート。
- `優等生ギャル`: 「目指せ優等生ギャル」ルート。マヂ情に厚く、友情も偏差値も盛る。
- どちらも同じステータス軸を使うが、初期値、導入モノローグ、リアクション、エンディングCG/本文が変わる。
- 結末帳は男主人公5種、ギャル主人公5種の計10エンディングを記録する。

## Target School Difficulty

Web版では、プロローグ後に志望校を選ぶ。偏差値が高いほど合格に必要な `学力`、合格番長に必要な `人望` / `メンツ`、定期的な受験圧と終盤の消耗が上がる。

| 志望校 | 偏差値 | 期間 | 合格学力 | 合格番長/優等生ギャルの人望/メンツ | 補欠ライン | 受験圧 |
| --- | ---: | --- | ---: | ---: | ---: | --- |
| 城北実学大学 | 52 | 3年間144週 | 74 | 42 / 42 | 学力64 + 人望68 + メンツ68 | 終盤のみ軽いストレス |
| 東都学院大学 | 60 | 3年間144週 | 82 | 48 / 48 | 学力72 + 人望70 + メンツ70 | 月末ストレス、終盤増加 |
| 帝王義塾大学 | 68 | 3年間144週 | 90 | 54 / 54 | 学力80 + 人望73 + メンツ73 | 月末ストレス、終盤に体力消耗 |
| 国立天嶺大学 | 74 | 3年間144週 | 96 | 60 / 60 | 学力88 + 人望76 + メンツ76 | 強めの月末ストレス、終盤に体力消耗 |

初期ステータスは試作初版より下げ、ストレス閾値も厳しくした。勉強だけを連打すると `孤独な合格` に寄り、仲間対応だけに寄せると高偏差値校には届きにくい。

## Ending Completion

- Web版では到達済みエンディングを `結末帳` に記録する。
- 記録対象は男主人公5種類、ギャル主人公5種類の計10種類。
- 記録はブラウザ内の `localStorage` に保存する。保存対象は結末IDのみで、秘密情報や個人情報は含めない。
- 未到達エンディングは `？？？` として伏せる。
- ローカル試作用に `記録消去` を用意する。

## Ending Presentation

- エンディング到達時は通常の校舎背景と立ち絵を隠し、結末ごとの一枚絵を全画面背景として表示する。
- BGMが再生中なら、エンディングごとの専用曲へ切り替える。BGMをOFFにしている場合は勝手に再生しない。
- ギャル主人公では同じ分岐条件でも、ギャル用の一枚絵と本文を表示する。
- `合格番長`: 校門前の合格発表と仲間の祝福。曲は `Victory`。
- `孤独な合格`: 夕暮れの校門で合格通知を見つめる。曲は `Sad Theme`。
- `補欠の伝説`: 教室で仲間に見守られる。曲は `Forgotten Victory`。
- `番長伝説`: 夕焼けの屋上で名を残す。曲は `Determination`。
- `不合格`: 雨の教室で次を見据える。曲は `Game Over`。

## Responsive Web Layout

- スマホ縦画面では、上部操作を3ボタン+音量1行に整理し、ステータスHUDを2列のコンパクト表示にする。
- ダイアログ枠は下部シートとして固定し、本文や選択肢が長い場合は枠内スクロールにする。
- 画面遷移時はダイアログ枠内のスクロール位置を先頭へ戻す。
- 低いスマホ画面と横向きでは、立ち絵を薄くするか非表示にして、ステータスとダイアログの可読性を優先する。
- エンディングCG/BGMはプレイ中のアイドル時間に事前読み込みし、到達時の白抜けを抑える。
