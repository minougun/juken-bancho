# 受験番長 Game Design

## Concept

「受験番長」は、熱血コメディ寄りのスケジュール管理ゲーム。番長として仲間を見捨てず、メンツとルックスを保ちながら、受験合格に必要な学力を積む。

## Core Loop

1. ターン開始時に現在ステータスを見る。
2. プロローグ後に志望校を選ぶ。
3. 予定カードから 1 枚選ぶ。
4. ステータスが変化し、低確率で事件が起きる。
5. 高校1年春から3年冬まで、全144週を進める。
6. BGMは1学期、夏休み、2学期、3学期の区切りで切り替わる。
7. 志望校ごとの受験圧で、終盤ほどストレスと体力消耗が増える。
8. ストレスが高いとルックスが下がり、顔立ち、表情、返事、身だしなみまで含めた対人コンディションが崩れて人望とメンツも落ちる。
9. 卒業式の時期に合否と主人公別の結末が決まる。

## Stats

- `学力`: 合格判定の主軸。
- `人望`: 仲間との関係。低すぎると「孤独」寄りの結末。
- `メンツ`: 番長としての威厳。低すぎると番長の座が揺らぐ。
- `ルックス`: 顔立ち、睡眠、清潔感、表情、声の張り、肌や髪の調子を含めた対人コンディション。高校生活では見た目も評価される現実から逃げず、ただし顔だけでなく生活の荒れや余裕のなさも一緒に扱う。
- `体力`: 行動の実行条件。低いと重い予定を選べない。
- `ストレス`: 高いほど不調になる。100 に近づくと効率が落ちる。

## MVP Scope

- スマホ縦画面。
- カード選択式。
- 高校3年間を144週で遊ぶ。
- UI 中心 + シルエット風の硬派な見た目。
- 外部 API、ログイン、DB、課金、広告は入れない。

## Protagonist Routes

- `受験番長`: 仁義とメンツを背負う硬派ルート。
- `優等生ギャル`: 「目指せ優等生ギャル」ルート。友情も偏差値も、自分の言葉で上げる。
- どちらも同じステータス軸を使うが、初期値、導入モノローグ、リアクション、エンディングCG/本文が変わる。
- 結末帳は男主人公5種、ギャル主人公5種の計10エンディングを記録する。

## Target School Difficulty

Web版では、プロローグ後に志望校を選ぶ。偏差値が高いほど合格に必要な `学力`、合格番長に必要な `人望` / `メンツ`、定期的な受験圧と終盤の消耗が上がる。

| 志望校 | 偏差値 | 期間 | 合格学力 | 合格番長/優等生ギャルの人望/メンツ | 補欠ライン | 受験圧 |
| --- | ---: | --- | ---: | ---: | ---: | --- |
| 城北実学大学 | 52 | 3年間144週 | 74 | 42 / 42 | 学力64 + 人望68 + メンツ68 | 終盤のみ軽いストレス |
| 東都学院大学 | 60 | 3年間144週 | 82 | 48 / 48 | 学力72 + 人望70 + メンツ70 | 月末ストレス、終盤増加 |
| 帝王義塾大学 | 68 | 3年間144週 | 90 | 54 / 54 | 学力80 + 人望73 + メンツ73 | 月末ストレス、終盤に体力消耗 |
| 国立天嶺大学 | 74 | 3年間144週 | 96 | 64 / 64 | 学力88 + 人望76 + メンツ76 | 強めの月末ストレス、終盤ストレス増加と体力消耗 |

初期ステータスは試作初版より下げ、ストレス閾値も厳しくした。勉強だけを連打すると `孤独な合格` に寄り、仲間対応だけに寄せると高偏差値校には届きにくい。

国立天嶺大学だけ、学力マイルストーンを持つ。1年終了時に学力70未満ならストレス+8、2年終了時に学力92未満ならストレス+10とメンツ-3、3年秋に学力96未満ならストレス+12。丸く立ち回るだけで後半に帳尻を合わせる戦略への対策として、序盤から学力を積む必要を作るが、balanced 戦略でも主ルートとして残る余地を持たせる。

五科目チェックは、元の30問を各1000バリアントへ展開可能な合計30,000問の出題プールとして扱う。初回ロードでは30,000件を実体化せず、出題時と復習帳表示時に `baseId + variantIndex` から必要な問題だけを生成する。問題本文を大量に直書きせず、数学は数値違い、英語は語句/接続表現違い、国語・理科・社会は論点違いのテンプレートで生成する。復習帳は出題されたバリアントIDだけを保存する。

## Looks And Stress

- ストレスが高い週は `ルックス` が下がり、同時に `人望` も少し落ちる。
- ルックスは、顔立ち、睡眠、清潔感、表情、声の張り、肌や髪の調子を含めた対人コンディションとして扱う。
- ルックスが低い状態が続くと、顔立ちへの自信のなさ、寝不足や焦り、返事の短さ、表情の硬さ、制服や髪の荒れが重なって、`人望` と `メンツ` が落ちる。
- 8週ごとに `ルックス` と `メンツ` の高低を見て、学校内での見られ方イベントを出す。高ルックス/高メンツは存在感で場を制し、高ルックス/低メンツは「見た目だけ」と見られ、低ルックス/高メンツは泥臭く信用され、低ルックス/低メンツは存在感を落とす。
- 睡眠や仲間との外出はルックス回復にも効く。勉強詰め込みや終盤の追い込みはルックスを削りやすい。

## Persona Improvements

- 初回HUDは `はじめる` / `続きから` / `メニュー` を基本にし、結末帳、回想帳、復習帳、音量、記録消去はメニュー側へ退避する。
- 導入はキャラ選択後に短い一人語りを戻し、主人公の名前、三年間の予定選択、学力/人望/メンツ/ルックスの同時管理を先に掴ませる。その直後に、徹平またはミナの進路相談という事件三択へ入る。ミナは最初から受験勉強の相棒ではなく、主人公が継続して机に向かう姿に触発され、高2後半から大学受験を自分の目標として口にし始める。途中で「置いていかれるだけ」と決めつけられることへ反発し、応援役ではなく自分の受験へ移る。
- 初回三択の結果には、得たもの、取りこぼしたもの、キャラ反応、ステータス変化を必ず出し、机/仲間/睡眠のどれかを選ぶ痛みを最初の90秒で伝える。
- 名前つきサブキャラとして、舎弟の徹平、親友のミナ、鬼塚先生、ライバル校の黒羽レンをカード結果やランダムイベントに出す。
- 12週ごとに固定事件を出し、徹平/ミナ、鬼塚先生、黒羽レン、受験票、願書写真、公開順位などの山場で144週を区切る。ギャルルートのミナは、高1では進路未定、高1後半に勉強を茶化しながら気にし始め、高2後半で大学受験への転向、高3で反発を経て並走へ変わる。各章では章タイトル、短期目標、関係レポートを表示する。
- 五科目チェックは強制ペナルティではなく任意ブーストにする。正解なら学力+1、不正解でも通常の予定効果は残り、見送ることもできる。正解/不正解には鬼塚先生や黒羽レンの反応を出し、3連続正解で集中コンボを表示する。
- メンツは暴力ではなく、約束と信頼を守る力として扱う。ルックスは顔立ちも含め、見た目が評価される不快な現実から逃げずにゲーム内で正面から扱う。両者の組み合わせで、学校が外見と信用をまとめて評価してしまう偏りをイベント化する。
- 会話音声はメニューの `VOICE` で明示的にONにする。VOICEVOXが使える環境では、受験番長、優等生ギャル、徹平、ミナ、鬼塚先生、黒羽レンへ別々のspeaker候補と速度/ピッチ/抑揚を割り当てる。主人公は危険な自動speaker fallbackを避け、VOICEVOX候補が欠ける場合はブラウザ/OSの日本語音声へ落とす。キャラ選択後の一人語りはnarratorではなく選んだ主人公castで読み、narratorは短い状況説明だけに限定する。一人語りは1画面あたり80〜100字以内を目安にする。重要イベントは表示文とは別に `voiceText` を持たせ、黒羽レン、国立天嶺大学、VOICEVOX、BGMなどの読みを固定する。

## Ending Completion

- Web版では到達済みエンディングを `結末帳` に記録する。
- 記録対象は男主人公5種類、ギャル主人公5種類の計10種類。
- 記録はブラウザ内の `localStorage` に保存する。保存対象は結末IDのみで、秘密情報や個人情報は含めない。
- 未到達エンディングは `？？？` として伏せる。
- ローカル試作用に `記録消去` を用意する。

## Ending Presentation

- エンディング到達時は通常の校舎背景と立ち絵を隠し、結末ごとの一枚絵を全画面背景として表示する。
- BGMが再生中なら、エンディングごとの専用曲へ切り替える。BGMをOFFにしている場合は勝手に再生しない。
- ギャル主人公では同じ分岐条件でも、ギャル用の一枚絵と本文を表示する。
- `合格番長`: 校門前の合格発表と仲間の祝福。曲は `Victory`。
- `孤独な合格`: 夕暮れの校門で合格通知を見つめる。曲は `Sad Theme`。
- `補欠の伝説`: 教室で仲間に見守られる。曲は `Forgotten Victory`。
- `番長伝説`: 夕焼けの屋上で名を残す。曲は `Determination`。
- `不合格`: 雨の教室で次を見据える。曲は `Game Over`。

## Responsive Web Layout

- スマホ縦画面では、上部操作を3ボタンに整理し、ステータスHUDを2列のコンパクト表示にする。
- ダイアログ枠は下部シートとして固定し、本文や選択肢が長い場合は枠内スクロールにする。
- 画面遷移時はダイアログ枠内のスクロール位置を先頭へ戻す。
- 低いスマホ画面と横向きでは、立ち絵を薄くするか非表示にして、ステータスとダイアログの可読性を優先する。
- エンディングCG/BGMはプレイ中のアイドル時間に事前読み込みし、到達時の白抜けを抑える。
