## Reviews（100点満点）

### 1. 高2男子・ヤンキー漫画好き・スマホ中心

**Score: 81 / 100**

辛口評価: 後半の低確率イベントと「仲裁」で、物語のオチと番長らしさのバランスが前より良くなった。それでも画面は主人公中心のままなので、漫画としての「顔の数」はまだ物足りない。

改善要求: 舎弟・ライバル・先生の最低限アイコン、仲裁選択時だけでも背景や差分を足す。

### 2. 20代女性・短編ノベルゲーム/乙女ゲーム経験者

**Score: 72 / 100**

辛口評価: カード別の一言リアクションでノベル感は上がった。ただし週をまたいだ関係の積み上げや、キャラ同士の連続シーンはまだ薄い。

改善要求: 好感やストレス帯で変わるセリフ差分、短い連続イベント（2ターンぶんの小さな弧）。

### 3. 30代男性・インディーゲーム実況/配信視聴者

**Score: 76 / 100**

辛口評価: 「受験票」「校長室」は配信向けの山になりうる。一方でイベントは配列先頭から1件だけ抽選のため、体感ではレアがさらに薄く感じる可能性がある。

改善要求: 抽選順・確率の意図をコメントまたは設計メモ化、超低確率の「大ゴマ」を別枠で管理。

### 4. 40代・教育/受験テーマに敏感な保護者層

**Score: 71 / 100**

辛口評価: フィクション注意と仲裁フレーバーで、暴力肯定に読まれにくくなった。とはいえ `tag: fight` や「自習室に殴り込み」「模試に特攻」など、言葉のメタファーはケア層によっては引っかかる。

改善要求: メタファー言い換え一覧の軽い監査、健全ルート（睡眠・補習）のエンディング到達感の強調。

### 5. Unity 移植を想定するクライアントエンジニア

**Score: 77 / 100**

辛口評価: カード・イベントの数値と文言のコアは `DefaultContent.cs` と揃っており移植しやすい。Web 側だけの `buildCardReaction` などは二重管理リスクが残る。

改善要求: 共有 JSON または生成パイプでマスタを1本化、`app.js` の最小分割（data / rules / dom）。

### 6. 低視力・スクリーンリーダー寄りのプレイヤー

**Score: 84 / 100**

辛口評価: HUD 要約と選択肢の音声向け効果要約は実用的で大きな前進。HUD 全体と行ごとの `aria-label` で情報が重複し、読み上げが長く感じる場合がある。

改善要求: 行ラベルに寄せて HUD を短くするか、`aria-describedby` で関係を整理。装飾として扱うなら主人公は `alt=""` と長文の役割分担を検討。

### 7. 1周10分以内を期待する通勤プレイヤー

**Score: 86 / 100**

辛口評価: 導入で時間目安が明示され、試作の期待値コントロールとして優秀。

改善要求: 任意で周回数や「あと何ターン」感をHUDに足す程度で十分。

## Overall

**Average: 77 / 100**（試作としての完成度・フォローアップの効果は明確。立ち絵・連続イベント・データ一元化で次の伸びしろ）

強み: トーン調整、短時間の明示、結果テキストの厚み、低確率イベント、a11y の実利。

弱み: キャラの顔の数、イベント体感確率の設計明示、Web/C# のセリフ二重管理リスク、残る喧嘩メタファー語。
